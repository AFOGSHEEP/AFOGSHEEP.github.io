亲手实现一个transformer

自注意力机制：

  • 查询 (Query, Q)：代表当前词元，它正在主动地“查询”其他词元以获取信息。
  • 键 (Key, K)：代表句子中可被查询的词元“标签”或“索引”。
  • 值 (Value, V)：代表词元本身所携带的“内容”或“信息”。

这三个向量都是由原始的词嵌入向量乘以三个不同的、可学习的权重矩阵 (W^Q,W^K,W^VW^Q,W^K,W^V) 得到的。整个计算过程可以分为以下几步，我们可以把它想象成一次高效的开卷考试：

  • 准备“考题”和“资料”：对于句子中的每个词，都通过权重矩阵生成其Q,K,V向量。
  • 计算相关性得分：要计算词A的新表示，就用词A的Q向量，去和句子中所有词（包括A自己）的K向量进行点积运算。这个得分反映了其他词对于理解词A的重要性。
  • 稳定化与归一化：将得到的所有分数除以一个缩放因子\sqrt{d_k}（是K向量的维度），以防止梯度过小，然后用Softmax函数将分数转换成总和为1的权重，也就是归一化的过程。
  • 加权求和：将上一步得到的权重分别乘以每个词对应的V向量，然后将所有结果相加。最终得到的向量，就是词A融合了全局上下文信息后的新表示。

  • 自注意力机制（Self-Attention）的核心思想是什么？
  • 为什么Transformer能够并行处理序列，而RNN必须串行处理？位置编码（Positional Encoding）在其中起什么作用？
  • Decoder-Only架构与完整的Encoder-Decoder架构有什么区别？为什么现在主流的大语言模型都采用Decoder-Only架构？

答：

  1. Self-Attention 的核心思想

核心就一句话：让序列中每个 token 都能“按需”查看其他 token，并动态决定关注谁、关注多少。

更形式化一点：

对每个 token，都会生成 Q（query）、K（key）、V（value）。
当前 token 用自己的 Q 去和所有 token 的 K 做相似度，得到一组权重（attention score）。
用这些权重对所有 token 的 V 做加权求和，得到当前 token 的新表示。
这带来的好处：

能建模长距离依赖（句首和句尾可以直接交互）。
关注模式是数据驱动、上下文相关的，不是固定窗口。
多头注意力（Multi-Head）可以并行学习不同关系（语法、语义、指代等）。
2. 为什么 Transformer 能并行，RNN 必须串行？

关键在计算依赖关系：

RNN：
h_t = f(x_t, h_{t-1})
第 t 步必须等 t-1 步算完，天然时间依赖，训练和推理都难并行（尤其训练时）。
Transformer（自注意力）：
一层内所有位置的 Q/K/V 可以同时算。
注意力矩阵本质是大规模矩阵乘法（GPU/TPU 非常擅长），所以训练可高度并行。
即使是 Decoder 用了因果 mask，训练时仍可把整段序列一次性喂入，mask 保证“看不到未来”，所以仍能并行算整段 loss。
补一句：
Decoder 在生成阶段仍是逐 token 自回归（因为下一个 token 依赖已生成结果），但这和 RNN 的“每层每步都串行”不是一个层面的瓶颈，且可用 KV cache 大幅优化。

  1. Positional Encoding 的作用

因为纯自注意力本身对输入是“集合式”的，不知道顺序。
位置编码就是把“第几个词”信息注入模型，让模型区分：

“猫追狗” vs “狗追猫”
邻近关系、远距关系、相对顺序等
常见做法：

绝对位置编码（sin/cos 或可学习向量）
相对位置编码（如 RoPE、ALiBi 一类思想）
它的本质作用：给注意力机制补上序列结构先验。

  1. Decoder-Only vs Encoder-Decoder 的区别

Encoder-Decoder（完整 Transformer）

Encoder：双向看输入，得到源序列表征。
Decoder：带因果 mask，自回归生成输出，并通过 cross-attention 读取 encoder 输出。
典型任务：机器翻译、摘要、问答（输入->输出映射明确）。
Decoder-Only

只有一个自回归 decoder 堆栈（causal self-attention）。
把“输入+输出”都当成同一串 token，训练目标是下一 token 预测。
典型代表：GPT 系列。
5. 为什么主流大语言模型多用 Decoder-Only？

主要是工程与规模化优势叠加：

统一目标简单且通用
直接做 next-token prediction，几乎所有文本都可用作训练数据，不需要复杂标注。

训练管线更简单
一个网络、一个损失，适配海量互联网语料最自然，扩展到万亿 token 训练更直接。

生成任务适配最好
聊天、写作、代码补全本质是连续生成，Decoder-Only 和使用场景高度一致。

in-context learning 能力强
把指令、示例、上下文拼在 prompt 里即可完成多任务，减少任务特定头和复杂架构需求。

推理系统成熟
KV cache、张量并行、流水并行、量化等优化在 Decoder-Only 上生态最成熟，部署成本更可控。

不是说 Encoder-Decoder 过时：

在一些“输入理解很重、输出相对短”的任务上（如高质量翻译）仍可能很强。
但在“统一大模型 + 通用生成”范式下，Decoder-Only 的性价比和扩展性目前最占优。
