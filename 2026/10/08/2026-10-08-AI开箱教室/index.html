从0开始学习的「AI 开箱教学」：把 Agent 从许愿机变成生产力的 60 分钟

项目地址：https://github.com/AFOGSHEEP/AI-Starter-Kit
一句话介绍：解压 → 双击一个文件 → 60 分钟后，零编程基础的小白拥有一个能自己读文献、跑统计、写文档的 AI Agent。

起因

我的一位朋友通过各种途径了解到 AI Agent——“把文件夹丢给 AI，它自己读文献、自己做对比表、自己写代码跑统计”——这对他来说这简直是梦想成真的许愿式功能。

但他一开始就卡住了： .md 是什么文件？

但这不是他一个人的问题，而是所有入门者共同的问题。市面上缺的不是 AI 工具，而是从”听说过”到”用起来”之间那一段路：API 是什么？Key 去哪领？Token 怎么计费？上下文窗口为什么会让 AI”失忆”？幻听文献怎么防？——这些概念每一个都有文章讲，但没有一条路把它们串起来，更没有人考虑过使用者是一个只会双击图标、被国内网络困住、预算按月计算的非计算机的研究生。

所以我决定做一个”开箱即用”的工具包，把他当真正的用户来设计。

三个现实约束，决定了产品形态

约束一：国内网络。 我们实测 claude.ai 直连返回 403 region unavailable——Claude Code 桌面版根本下不来；GitHub 直连慢到断点续传。所以方案改成：Node.js 走华为云镜像、CC Switch 安装包（v4.0.4，sha256 校验过）直接塞进压缩包、Claude Code 用 npmmirror 国内 CDN 一键脚本装。最终形态是：全程不碰 GitHub 和 claude.ai。

约束二：政策。 只能用国内 API。主推 DeepSeek（官方提供 Anthropic 兼容端点，Claude Code 可以无缝把”发动机”换成 DeepSeek），按量付费、学生月费 10~30 元、晚上周末半价——这套费用观我写成了专门的课程和可交互计算器。

约束三：用户画像。 他不知道什么是终端、JSON、密钥。所以任何需要”打开命令行输入什么”的步骤都是设计缺陷。

产品形态的三个决定

决定一：教学是网页小程序，不能是文档。 第一版我写了一堆 markdown，被当场打回：”他都不知道 md 是什么，你给他写 md？”于是全部教学重构成一个单文件 HTML：双击就能在浏览器里上课，6 节概念课全部用生活化类比（以大家都熟悉的就医流程为例：API Key = 就诊卡、Token = 计费单位、缓存命中 = 复诊免问诊费——类比体系换成任何人群熟悉的场景都成立），每节课后有小测，全对才解锁”已完成”，进度自动保存。

决定二：安装只需要”双击一个文件”。 于是有了 ①先双击我-开箱向导.bat：一个 PowerShell 向导自动检测装没装、依次调起安装器、写入配置前自动备份。更有意思的是向导和教学网页的联动——本地网页在 file:// 协议下有跨域限制，没法直接通信，我用了 JSONP 风格的方案：向导每一步把状态写成 wizard-status.js，网页用动态 script 标签每 1.2 秒轮询，于是浏览器里能看到实时进度条、四步状态卡和滚动日志。全程唯一需要用户动脑的事：去领一张 DeepSeek”就诊卡”（密钥）——而这一步，网页里有图文教学，教到”回黑色窗口右键粘贴”这个级别的细节。

决定三：验收必须机器做，不能靠自觉。 装机清单里”打勾”谁都会，所以关键步骤全部机器验收：密钥自检台直连官方接口做格式检查→查余额→发一条真实测试消息（顺便让用户亲眼看到这条消息花了几分钱）；CLAUDE.md 文件拖进网页自动验文件名（抓”存成了 .txt”这个新手第一大坑）、编码（抓 ANSI 乱码）、内容完整性；另有一个 PowerShell 体检助手真读 ~/.claude/settings.json，发现地址还指向 api.anthropic.com 会直接告诉你”这就是要求登录的根源”。

拆开看：这个工具包里到底有什么

开箱向导：四步顺序是设计出来的

向导不是”装三个软件”那么简单，顺序本身就是功能：① Node.js（离线 MSI）→ ② CC Switch（先备好”换发动机”的图形工具）→ ③ 密钥（验证后写入配置）→ ④ Claude Code。

把 Claude Code 放最后的原因很具体：它首次启动时如果 ~/.claude/settings.json 里还没有 DeepSeek 的端点和密钥，就会掉进 Anthropic 的登录引导——对国内用户来说是一堵死墙。反过来，先配好配置再装本体，第一次输入 claude 回车就直接可用。向导的密钥步骤甚至把”跳过”的后果写在了提示里：”跳过的话，claude 第一次打开可能要求登录，记得回来配。”

每一步有七种状态（pending/running/waiting/need_key/ok/error/skipped），实时写进状态文件；waiting 状态会在网页上变成人话：”🖱️ 等你在弹出的安装窗口里点「下一步」”。任何一步失败不阻塞后续，收尾输出 n/4 完成度和修复指引。

教学教室：一个 75KB 的单文件网页

  • 六节概念课 + 14 道测验：聊天 vs Agent、API 与 Key、Token 与计费、上下文与记忆、提示词、幻觉与红线。测验全对才解锁完成——不是为难人，是让”我懂了”变成可验证的事
  • 上下文感知侧栏：左侧常驻任务栏，进入不同页面自动切换内容——课程页显示六课进度（可点击直达并展开）、装机页显示五步分组进度、费用页实时同步估算月费、场景页显示索引。外加一张全局”下一步该干嘛”卡，替用户记着 todo
  • 费用计算器：三个滑块（每日文献量/任务量/每月赶工大活）× 模型档位 × 峰谷时段，实时出月费，画成和包月方案的对比条；填入密钥还能直连官方查真实余额、换算”还能用几个月”
  • 急救站 14 条：401/402/429、模型列表空、配置不生效、登录墙、Key 泄露……每条都是”症状 + 按方抓药”的手风琴卡
  • 8 个场景提示词：文献速读、多文献综述、Excel 全自动统计、写作润色、出题、PPT、生活、VOCALOID。结构统一为”角色+目标+材料+输出格式+约束”——教的是写提示词的方法，不只是给鱼

机器验收：三个”查作业”装置

  1. 密钥三级体检：边打字边校格式（分别提示”你可能只复制了一半”/“登录密码不是 Key”）→ 查余额（有效就自动勾选装机项；余额为 0 提前预告 402）→ 点火测试（真发一条消息，把模型回复、token 用量、折算花费展示出来——用户第一次直观看到”按 token 计费”是什么意思）
  2. CLAUDE.md 拖拽验收：网页 FileReader 读文件，专抓三个新手经典翻车点——文件名存成 CLAUDE.md.txt、编码存成 ANSI（检测 U+FFFD 替换符）、内容只贴一半；每个错误给具体修法。另配”一键下载”按钮（Blob 直出），从根上杜绝保存错误
  3. AI 装机体检助手：独立的 PowerShell 程序，真读系统——命令、目录、注册表三路探测装没装；解析配置文件报告 Base URL 指向和密钥掩码；还能一键写入推荐配置（时间戳备份）、联网点火、打开官方下载页

降级链：Plan A → B → C

给新手的工具必须有”全挂了怎么办”的答案：

  • Plan A：双击开箱向导，全自动
  • Plan B：照安装说明手动双击五个安装包/脚本
  • Plan C：就算所有 .bat 都被杀软拦死——装完 Node 后打开 cmd，右键粘贴一行命令（npm config set registry https://registry.npmmirror.com && npm install -g @anthropic-ai/claude-code）也能装完。这行命令只依赖第 1 步装上的 npm，而”终端里右键=粘贴”这件事，教学程序里教过

踩坑实录（这次全踩了一遍）

  1. claude.ai 403：不是玄学，是确定的 region unavailable。直接改变了产品架构：离线包优先，官网链接一律不给。
  2. DSH 下载渠道：第一版我把 DSH 桌面版的下载指向 GitHub Releases——被一句话点醒：”他连 GitHub 都上不去你指他去 GitHub？”正确答案：官网 deepseek.com 首页就有 Download Desktop（国内直连），微软商店是备选。
  3. npm 到底要不要代理：网上说法不一。我做了受控实测：清空代理变量、确认 npm proxy=null，直连 npmmirror 完整安装 claude-code——18 秒装完，含 245MB 的 Windows 原生二进制（它以平台子包分发，npmmirror 全量同步，没有隐藏的外网依赖）。从此文档里敢写死”不需要代理”。
  4. 安装顺序与登录墙：把 Claude Code 放第一步装，用户手一点开就撞登录墙。调整为”CC Switch 先装、密钥先配、本体最后”，问题消失。
  5. PowerShell 5.1 的 BOM 坑：无 BOM 的 UTF-8 脚本被当 ANSI 解析，中文必炸。所有 ps1 都补 UTF-8 BOM，测试脚本也逃不掉。
  6. file:// 的跨域：网页 fetch 本地状态文件被浏览器拦。JSONP（动态 script 标签）是 file:// 下唯一优雅的本地通信方式。
  7. bat 的 ASCII 坑：bat 文件内容里的中文路径会按 GBK 解析必乱码——入口 bat 只写 ASCII，用 for %%f in (*.html) 通配打开教学页。
  8. .bat 一闪而过：杀软拦截、执行策略、双击姿势都可能是原因。入口自带 -ExecutionPolicy Bypass，急救站有专门条目，Plan C 兜底。
  9. CC Switch 的重写行为：它切换供应商时会整体重写 settings.json，自定义字段可能被清（上游已知 issue）。对策：本工具包所有写入都先做时间戳备份。
  10. AI 生图的中文字：用 Qwen 系模型生成带中文台词的表情包，出来的是”曳友俫！”式伪汉字；换大参数编码器又被 LoRA 维度锁死。结论：这类小编码器+LoRA 组合的文字渲染有结构性上限，图字分离（生成无字图+GDI+ 程序叠字）才是正解。这条支线最后整个砍掉了，但结论通用。

教学设计的私心

工具包里我最在意的不是功能，是三句话：

  1. **”AI 给的文献必须核实”**——幻觉课放在必修位，编造出处、似是而非的数据这些高危项写成了清单；
  2. **”敏感数据先脱敏”**——能定位到个人的字段（姓名/证件号/日期）先删或替换再上传；
  3. **”AI 是助理，不是决策者”**——CLAUDE.md 人设模板里写死了”引用必须真实、不确定就明说、最终决策永远由人负责”。

给新手的 AI 工具，如果不教这些，就是在造事故。

二编（2026-10-09）：安装脚本 v2.0 —— 先查地基，再装本体

上面正文保持初版发布时的样子，一字未动。这次的改动只写在这一节里。

起因：初版里埋着的一个坑

回头复查安装脚本，第一眼就看到了自己偷懒的地方：它只用 where node 判断”有没有装 Node.js”，从来不问版本。而 Claude Code 官方包的 package.json 里写着 engines.node >= 22——一台装着 Node 16 的电脑（很常见，很多老教程还停在 14/16 时代）会被 npm 直接拒绝安装，或者装完了敲 claude 抛一串没人看得懂的错。用户拿到这种结果的唯一结论是：”这东西我用不了。”

而这本该是脚本的责任：检测”存在”和检测”可用”是两件事。工具的边界应该按官方声明的 engines 字段写死，而不是按我记忆里的教程写。

改法：体检 → 提醒 → 自动补 → 再装 → 再验

v2.0 把安装从”一条命令”改成了带前置体检的流水线。装之前先逐项检查八件事：

  1. Node.js 是否存在且 ≥ 22（不达标就直接说清”你的是 v16.20.2，Claude Code 要求 22 以上”，而不是抛错）
  2. npm 是否可用（Node 自带，单独缺了通常是安装不完整）
  3. Node 目录与 npm 全局目录是否在 PATH 里——“装好了却敲不出 claude”九成卡在这里
  4. 磁盘剩余空间（低于 2GB 先提醒：装到一半失败多半是它）
  5. 下载源是否可达（npmmirror 不通就自动回退官方 npm 源）
  6. 离线包是否完整（离线安装模式才查）
  7. 是否已经装过 Claude Code、是否有 claude 正在运行（离线覆盖前必须先关）
  8. 有没有管理员权限（缺了就自己申请提权，弹一次 UAC）

缺什么就自动补什么：

  • Node 走三级降级：礼包自带 MSI（装之前校验 Authenticode 签名，签名人是 OpenJS Foundation）→ 从华为云镜像下载同一版本 → 系统自带的 winget
  • PATH 缺项：写回用户级环境变量并刷新当前会话，不必重开电脑
  • npm 缺失：用 Node 安装包做一次修复安装
  • 装完再验一遍 claude --version：命令真能跑才叫成功；跑不动就明确给下一步指令，而不是留个黑洞
  • 每次运行都在安装包目录留一份日志。我越来越确信：教程作者最需要的是用户手里那行报错，而不是”我装不上”这四个字

顺手加了”只想体检、不想动我电脑”的入口：安装ClaudeCode-只检测环境.bat，跑完只打印结论、零改动——给不放心脚本的人留一条退路，在教学产品里这件事比多一个功能重要。同一套检测逻辑也接进了开箱向导和装机体检助手：向导第 1 步问的不再是”有没有 node”，而是”版本够不够”。

三个入口：一键联网安装.bat（推荐）／离线安装.bat（没网时）／只检测环境.bat（纯体检）。老用户不需要重装，用新的 安装包 目录覆盖旧的，或者直接双击新脚本即可，密钥和已有配置都不受影响。

这次踩的新坑（三条）

  1. PowerShell 的别名优先级高于函数：体检脚本里我定义了一个 function H 用来打印小标题，结果它从来没生效过——h 是 Get-History 的内置别名，而别名的优先级高于函数，每次调用都被解析成 Get-History "第 1 部分"，往 stderr 喷参数绑定错误。更讽刺的是这类错误不中断执行，于是”小标题不显示 + 莫名报错”这个现象被我忽略了很多版。改名 Section 后世界安静了。
  2. cmd 的括号块里不能出现括号：我在 if errorlevel 9009 ( ... ) 块里写了一行带括号的英文提示，cmd 解析这个块时遇到里面的 ) 就提前收尾，剩下的 . 直接报 . was unexpected at this time.——而这段代码本只在”PowerShell 都起不来”时才该跑，却每次运行都在偷偷报错。教训：括号块内不写括号，宁可换行重写。
  3. 编辑器会悄悄丢掉 UTF-8 BOM：中文 .ps1 没有 BOM 就会被 PowerShell 5.1 当 ANSI 解析，中文全变乱码、语法直接崩。第 5 条坑早就踩过，这次的升级版是”改一个字就炸”——因为某些编辑器保存时会把 BOM 吃掉。现在”补 BOM + 统一 CRLF + 过一遍语法解析”是提交前的固定收尾动作。

验证方式（尽量不靠”我觉得能行”）

把 PATH 里的 node 摘掉模拟”没装环境”，把最低版本临时抬到 99 模拟”版本过低”，两条分支都能正确报出问题并生成修复计划；本地 MSI 的 Authenticode 签名校验通过；两个 Node 下载地址与 npm 镜像都实测返回 200；四个 PowerShell 脚本提交前全部过一遍语法解析；三个 bat 走完整链路（含中文路径）实跑过，退出码 0。

唯一没做的是真跑 msiexec 装卸 Node——不想在自己机器上反复折腾，所以自动安装路径目前只到”演练 + 各环节单独验证”。等哪天有台真实缺环境的机器跑一遍，这句会补上实测结果。

获取到的更新

仓库提交 b6fce81 已推送，GitHub 上 AFOGSHEEP/AI-Starter-Kit 的快照（Code → Download ZIP）随之更新，解压即含 v2.0 的全部脚本。离线包里那个 244MB 的原生二进制超过 GitHub 单文件 100MB 上限，不进仓库，只随发行压缩包分发。
